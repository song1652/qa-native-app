# 로컬 QA 복원력 장애 주입 설계

## 목표

실기기 없이도 장시간 실행, Android 에뮬레이터와 iOS 시뮬레이터 연결 상실·복구,
Appium/관리 프로세스 비정상 종료, 관측성 아티팩트 누적 정리를 빠르고 반복 가능한
자동 테스트로 검증한다.

## 범위와 안전 원칙

- 실제 Android/iOS 기기를 연결하거나 끊지 않는다.
- 사용자가 실행 중인 Appium, 에뮬레이터, 시뮬레이터 프로세스를 종료하지 않는다.
- 시간 경과는 주입 가능한 `now` 값으로 재현한다.
- 프로세스 검증은 테스트가 직접 생성한 짧은 수명의 자식 프로세스만 사용한다.
- 파일 삭제는 pytest의 `tmp_path` 아래에서만 수행한다.

## 구성요소

### 실행 프로세스 복구

`shared.py`의 PID 저장·복원 계약을 테스트한다. 살아 있는 테스트 자식 프로세스는
서버 재시작 복원 시 실행 중으로 재등록되고, 이미 종료된 PID는 복원 목록과 상태
파일에서 제거되어야 한다. 장시간 실행은 실제로 기다리지 않고 살아 있는 프로세스와
저장된 PID 상태로 표현한다.

### 가상 디바이스 상태 복구

기존 `detect_android_runtime`과 `detect_ios_runtime`에 순차적인 adb/simctl 응답을
주입한다. 동일 상태 객체가 `running -> stopped -> running`으로 복구되는 전체 흐름을
Android/iOS 각각 검증한다. 이는 실제 기기나 에뮬레이터를 변경하지 않는다.

### Appium 비정상 종료

관리 PID는 살아 있으나 HTTP 상태가 끊긴 경우 `error`, PID까지 종료된 경우
`stopped`, 외부 Appium만 응답하는 경우 `external`로 판정되는 계약을 검증한다.
stale Appium 시작 경로는 기존 종료 대기 경계를 사용하며 사용자 프로세스를 직접
건드리지 않는 테스트 더블로 검증한다.

### 아티팩트 보존 정리

보존 정책을 `agents/dashboard/utils/artifact_retention.py`의 독립 서비스로 이동한다.
서비스는 `runs_dir`, `max_runs`, `max_total_mb`, `now`, `active_grace_hours`를 받아
삭제한 run과 확보한 바이트를 결과로 반환한다. 최근 미완료 run은 보호하고, 6시간이
지난 미완료 run은 stale로 간주하며, 완료 run은 오래된 순서로 개수·용량 한도를
충족할 때까지 삭제한다. 관측성 런타임과 파이프라인은 같은 서비스를 사용한다.

## 검증

- 각 기능은 실패하는 테스트를 먼저 작성한다.
- 장애 주입 집중 테스트를 실행한다.
- 전체 dashboard 및 observability 회귀 테스트를 실행한다.
- 현재 로컬 Android/iOS/Appium 상태는 읽기 전용 API로만 확인한다.
