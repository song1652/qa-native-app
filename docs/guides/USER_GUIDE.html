화면에서 TC 작성부터 실행 결과 확인까지

QA Control Center에서 Android·iOS 테스트를 준비하고 실행하는 방법입니다. 왼쪽 메뉴 이름과 버튼은 현재 밝은 UI를 기준으로 설명합니다.

아래 이미지는 2026-10-02에 실제 대시보드를 1440px 너비로 열어 촬영한 화면입니다. 실행 결과와 연결 상태를 그대로 보여 주며, 성공 결과를 임의로 넣은 예시가 아닙니다. 숫자·기기·스위트 이름은 사용 중인 환경에 따라 달라집니다. 이미지를 누르면 원본 크기로 볼 수 있습니다.

처음 시작한다면: 환경 설정에서 Appium과 기기를 준비한 뒤, TC 스튜디오 또는 화면 캡처로 작성에서 TC를 만드세요. TC가 이미 생성되어 있으면 빠른 실행으로 이동합니다.

대시보드

최근 실행 현황과 Appium·기기 연결 상태를 확인하는 첫 화면입니다. 상단의 실행 상태를 펼치거나 왼쪽 메뉴에서 작업 화면으로 이동합니다.

무엇을 확인하나요?

  • 최근 실행: 실행 시각, 플랫폼, 통과·실패 집계와 최근 기록을 확인합니다.
  • 파이프라인 상태: 분석부터 자동 복구까지 진행한 단계를 확인합니다.
  • 환경 상태: Appium과 Android·iOS 기기 상태를 확인하고, 설정을 바꿀 때는 환경 설정으로 이동합니다.
  • 전체 기록 보기: 실행 기록에서 실행별 통과율과 소요 시간을 비교합니다.

메뉴를 다시 선택하면 해당 화면의 목록을 새로 읽습니다. 브라우저의 뒤로 가기·앞으로 가기와 새로고침에서도 선택한 화면 주소가 유지됩니다.

초기화 구분: 대시보드 초기화, 각 실행 화면의 리셋, 기록 초기화, 리포트의 선택 삭제는 서로 다른 작업입니다. 표시되는 확인 창의 내용을 읽고 선택하세요.

TC 스튜디오

엑셀 TC를 가져오거나 기획 자료로 초안을 만들고, 검토한 TC를 라이브러리에서 관리합니다. 왼쪽 메뉴의 TC 스튜디오 또는 /tc-studio로 엽니다.

네 개의 작업 탭

탭작업 순서
기획 정보 · 생성텍스트·PDF·DOCX를 올리거나 내용을 붙여 넣고, 시트·분류·작성 프로필·대상 플랫폼을 선택해 초안을 생성합니다. 연결 설정이 준비되면 URL·Confluence·Figma 자료도 사용할 수 있습니다.
라이브러리가져오거나 승인한 TC를 조회·수정합니다. 스위트, 플랫폼과 결과 필터로 범위를 좁힙니다.
초안 검토생성된 초안의 출처·내용·중복 여부를 확인합니다. 수정 후 승인할 항목을 선택합니다.
내보내기그룹 폴더와 ID 접두어를 지정하고 미리보기를 확인한 뒤, 승인된 TC를 플랫폼별 Markdown으로 반영합니다.

처음 사용하는 환경에서는 기본양식 스위트와 기본 시트로 시작할 수 있습니다. 초안 생성은 연결한 모델·CLI 설정에 따라 동작하며 해당 서비스의 사용량이 발생합니다.

엑셀 가져오기와 플랫폼 결과 비교

  1. 엑셀 가져오기에서 .xlsx 파일을 선택합니다.
  2. 시트·헤더·열 매핑과 미리보기를 확인한 뒤 가져올 위치를 선택합니다.
  3. 라이브러리에서 Android와 iOS 결과를 각각 확인합니다. And·iOS 결과가 다른 것만 필터로 차이를 비교할 수 있습니다.
  4. 결과를 일괄 변경할 때는 대상 플랫폼을 먼저 선택합니다. 엑셀로 다시 내보낼 때도 플랫폼별 결과를 확인합니다.

2줄 헤더의 환경 → And | iOS와 1줄 헤더의 Android | iOS를 인식합니다. 한쪽이 NA인 TC는 다른 플랫폼 전용일 수 있으므로 상세 화면에서 대상 플랫폼을 확인하세요.

승인 TC를 실행 가능한 입력으로 내보내기

내보내기의 미리보기에서 저장 경로와 파일 충돌을 확인합니다. 플랫폼별 출력 위치는 testcases/android/{group}/ 또는 testcases/ios/{group}/입니다. 기존 파일을 덮어쓸 때는 해당 선택을 확인합니다.

내보내기에서 연결한 파이프라인은 UI 분석을 생략하고 코드 생성·린트·실행을 진행합니다. 직접 파이프라인으로 들어간 경우에는 현재 단계 선택을 확인합니다. 엑셀 가져오기를 잘못 적용했다면 스위트를 통째로 삭제하기 전에 엑셀 가져오기 → 가져오기 이력에서 해당 작업의 되돌리기를 확인하세요. 내보낸 Markdown을 직접 수정한 경우에는 변경을 덮어쓰지 않도록 되돌리기를 거부합니다. 표시된 변경 안내를 확인한 뒤 처리합니다.

화면 캡처로 작성

Capture Studio에서 실제 앱 화면과 UI 트리를 보며 동작을 기록하고, Locator를 검토한 뒤 TC를 저장합니다. 기획 문서로 작성하는 TC 스튜디오와 함께 사용할 수 있습니다.

세션 설정 → 동작 기록 → Locator 검토 → 저장 및 생성

  1. 세션 설정: OS, 실행 대상, 앱 정보와 TC 그룹명을 입력합니다. Android는 앱 패키지와 Activity, iOS는 Bundle ID와 기기를 확인합니다.
  2. 환경 확인: Appium과 기기 상태를 확인한 뒤 활성화된 세션 시작을 누릅니다.
  3. 동작 기록: 미러 화면과 UI 트리에서 요소를 확인하고 탭·입력·스크롤·뒤로·대기·검증 동작을 필요한 순서로 추가합니다. 화면이 바뀌면 UI 트리를 새로 읽고 대상 요소를 다시 확인합니다.
  4. Locator 검토: 후보가 원하는 요소 하나만 가리키는지 검증합니다. 여러 요소와 일치하거나 찾지 못하면 후보와 화면을 다시 확인합니다.
  5. 저장 및 생성: TC ID와 제목을 입력하고 미리보기로 순서·입력값·검증 조건을 확인한 뒤 저장 및 생성을 누릅니다.
  6. 세션 종료: 작성이 끝나면 세션을 종료하고, 빠른 실행에서 생성된 폴더와 기기를 선택합니다.

TC Markdown은 testcases/{platform}/{group}/, 생성 코드는 tests/generated/{platform}/{group}/에서 확인합니다. 기기별 화면 구조와 앱 Activity는 다를 수 있으므로 현재 연결된 앱의 정보를 사용하세요.

직접 해보기 — 설정 검색창에서 Bluetooth 입력 확인

Android 설정 앱을 대상으로, 검색창을 열고 Bluetooth를 입력한 뒤 해당 문자열이 입력되었는지 확인하는 흐름입니다. 검색창의 Locator와 Activity는 현재 기기의 UI 트리에서 확인합니다.

  1. TC 그룹명을 capture_studio_e2e처럼 지정하고 설정 앱 세션을 엽니다.
  2. 검색창 요소를 선택해 Locator를 검증하고 탭 동작을 기록합니다. 수동 기록 모드에서는 실제 앱 화면도 검색 입력 화면으로 이동시킵니다.
  3. 화면 전환을 기다리는 대기 동작을 추가합니다. UI 트리를 새로 읽고 검색 입력 필드를 선택합니다.
  4. 입력에서 Bluetooth를 기록합니다. 실제 앱에서도 같은 값을 입력해 다음 상태를 확인합니다.
  5. 필요한 대기 뒤 검증 → 텍스트 확인으로 Bluetooth를 확인하도록 기록합니다.
  6. TC ID를 입력하고 미리보기에서 아래 동작 순서를 확인합니다. 저장 후 Capture 세션을 종료하고 생성된 폴더만 빠른 실행합니다.
  • 검색창 탭
  • 대기
  • Bluetooth 입력
  • 대기
  • 텍스트 확인

완료 확인: 저장 상태와 생성 파일을 확인하고, 실행 결과에서 해당 TC의 최종 결과·시도별 증거·오류를 확인합니다. 이 순서는 작성 예시이며 통과를 보장하는 실행 결과가 아닙니다.

MCP 연동과 Livetail

Capture 세션을 연 뒤 MCP 클라이언트에서 http://localhost:8767/mcp 서버에 연결하면 화면 확인과 기기 조작을 요청할 수 있습니다. 클라이언트의 MCP 서버 설정에서 이 주소를 등록합니다. 연결 상태는 Capture 세션 바의 MCP 표시에서 확인합니다.

도구용도
screenshot, hierarchy, screen_info현재 화면·UI 계층·화면 상태 확인
device_tap, scroll, input_text, back기기에 탭·스크롤·문자 입력·뒤로 동작 전달
generate_test_case, clear_actions기록된 동작으로 TC 생성 또는 동작 목록 초기화

예를 들어 “현재 화면과 UI 트리를 확인해 줘”, “검색창에 Bluetooth를 입력해 줘”처럼 요청할 수 있습니다. 세션이 없으면 기기 제어 도구가 session_not_active 오류를 반환하므로 세션 상태부터 확인합니다.

Livetail에서 사용자·MCP·파이프라인 출처별 이벤트를 확인합니다. 수동 동작은 user, MCP 동작은 mcp, 파이프라인 이벤트는 pipe로 구분됩니다. 저장할 동작 출처를 선택하는 경우, 실제 실행 단계와 화면 확인용 이벤트가 섞이지 않았는지 미리보기로 확인하세요.

같은 기기 세션 충돌: Capture 세션을 열어 둔 채 같은 플랫폼의 테스트를 실행하면 충돌할 수 있습니다. 작성 세션을 종료한 뒤 실행하세요. 연결이 끊겼다면 기기 상태와 Appium을 확인하고 세션 재연결을 사용합니다.

파이프라인

TC Markdown을 입력으로 분석·코드 생성·린트 검사·테스트 실행·자동 복구를 순서대로 진행합니다. 준비된 단계만 개별로 실행할 수도 있습니다.

전체 실행 순서

  1. Android / iOS 중 실행할 플랫폼을 선택합니다.
  2. 실행할 TC 폴더의 체크박스를 선택합니다. 전체 선택·전체 해제로 범위를 조절합니다.
  3. 기기의 라디오 버튼에서 실행 대상을 선택합니다. 미연결 기기는 선택할 수 없습니다.
  4. 증거 수집의 보존 정책을 선택합니다. 정책 설명은 실행 결과와 증거를 참고합니다.
  5. 전체 실행을 누르고 단계별 상태와 실행 로그를 확인합니다. 필요한 경우 해당 단계의 취소 버튼을 사용합니다.
  6. 완료 후 실패 요약과 리포트를 확인합니다. 결과는 실행된 TC와 앱 상태에 따라 달라집니다.

단계별 의미

  • UI 분석
  • 코드 생성
  • 린트 검사
  • 테스트 실행
  • 자동 복구
화면 단계설명
UI 분석앱 UI 계층과 필요한 화면 정보를 수집합니다.
코드 생성TC Markdown과 Locator 정보를 기반으로 실행 코드를 만듭니다.
린트 검사생성된 코드의 검사 오류를 확인합니다.
테스트 실행선택한 플랫폼·기기에서 pytest 테스트를 실행합니다. 재시도가 설정되어 있으면 실패 항목을 다시 시도합니다.
자동 복구실패 Locator를 다시 분석해 복구 가능한 후보를 확인합니다. 복구 결과와 남은 실패를 로그에서 확인합니다.

실행에 필요한 Appium과 기기는 환경 설정에서 준비합니다. 초기화·분석·생성 같은 작업은 선택한 플랫폼과 앱에 적용되므로 실행 전 대상을 확인하세요.

빠른 실행

이미 생성된 tests/generated의 코드를 실행합니다. 분석·코드 생성·린트가 필요한 TC는 먼저 파이프라인에서 준비합니다.

테스트 실행

  1. 실행할 Android / iOS를 선택합니다.
  2. 기기 라디오에서 연결된 기기를 선택합니다. 파이프라인과 빠른 실행은 같은 플랫폼의 기기 선택을 공유하고, Android와 iOS 선택은 각각 유지합니다.
  3. 테스트 폴더의 체크박스를 선택합니다. 전체 선택으로 현재 플랫폼의 폴더 전체를 선택하거나 해제합니다.
  4. 보존 정책과 자동 복구 건너뛰기 선택을 확인합니다. 이 체크박스가 선택되어 있으면 자동 복구를 건너뜁니다.
  5. 테스트 실행을 누릅니다. 실행 로그와 완료 상태를 확인한 뒤, 아래 결과 영역에서 TC와 시도를 선택합니다.

기기 목록을 새로고침했을 때 선택한 기기가 미연결이면 연결된 다른 후보가 선택될 수 있습니다. 실행 버튼을 누르기 전에 현재 선택 표시를 다시 확인하세요. 키보드로는 라디오에 초점을 옮긴 뒤 방향키·Space로 선택할 수 있습니다.

실행 결과와 증거

보존 정책확인할 내용
실패 시만실패·불안정 결과의 증거를 보존합니다. 정상 통과한 실행에는 보존된 증거가 없을 수 있습니다.
항상성공을 포함해 수집한 증거를 보존합니다. 수집 지원 여부와 저장 결과를 함께 확인합니다.

증거 화면에서 TC를 선택하고 시도별 영상·스크린샷·시스템 로그를 확인합니다. 파일이 없으면 보존 정책과 수집 실패 안내를 먼저 확인합니다. iOS 실기기의 증거 수집처럼 지원하지 않는 대상도 있습니다.

재시도 결과: 재시도 뒤 최종 setup·call·teardown이 모두 통과한 TC는 통과 집계에 포함됩니다. 한 번 실패한 뒤 통과한 항목은 실행 증거 화면에서 FLAKY로 표시될 수 있습니다. 최종 합계와 각 시도의 결과를 함께 확인하면 최초 실패를 놓치지 않습니다.

리포트

생성된 HTML 리포트를 검색하고 대시보드 안에서 열어 봅니다. 넓은 화면에서는 목록이 왼쪽, 미리보기가 오른쪽에 표시되며 좁은 화면에서는 위아래로 배치됩니다.

목록에서 리포트 열기

  1. 리포트 이름 검색과 정렬을 사용해 파일을 찾습니다. 필요하면 새로고침을 누릅니다.
  2. 파일 행 또는 열기로 미리보기를 엽니다. 각 항목의 새 탭은 별도 탭에서 열고, 삭제는 해당 파일을 삭제합니다. 체크박스는 삭제할 파일 선택에만 사용합니다.
  3. 여러 파일을 정리할 때만 체크박스로 선택하고 선택 삭제를 누릅니다. 확인 창에서 선택 내용을 확인합니다.
  4. 미리보기의 닫기는 뷰어를 닫는 작업이며 파일 삭제가 아닙니다.

리포트 파일은 tests/reports/report_{platform}_{날짜}_{시각}_{식별자}.html 형식으로 저장됩니다. 대시보드에서 열면 이전에 저장된 앱 QA 리포트도 현재 밝은 표시 스타일로 보이며, 원본 실행 내용과 증거 파일은 유지됩니다.

그룹·필터·실패 상세 읽기

  • 상단 그룹 칩: 전체 또는 필요한 그룹을 선택합니다.
  • 제목과 통계: 전체·통과·실패·건너뜀·통과율을 한 줄에서 확인합니다.
  • 그룹 제목: 첫 그룹은 기본으로 펼쳐집니다. 제목을 누르거나 키보드 Enter·Space로 펼침 상태를 바꿉니다.
  • 제목 아래 필터: 전체·통과·실패와 필요한 경우 건너뜀을 선택합니다. 항목이 많으면 페이지를 전환합니다.
  • TC 상세: 행을 펼쳐 사전 조건·단계·기대 결과와 오류를 읽습니다. 전체 오류 보기에서 상세 오류를 확인하고, 시도 버튼으로 보존된 증거를 바꿉니다.

리포트 제목 옆에는 별도의 대시보드 이동·인쇄 버튼이 없습니다. 다른 작업 화면은 왼쪽 메뉴로 이동하며, 인쇄가 필요하면 브라우저의 기본 인쇄 기능을 사용합니다. Locator를 고치려면 실패 정보를 확인한 뒤 작성 화면과 파이프라인으로 돌아가 수정·생성·실행합니다.

실행 기록

같은 브라우저에서 기록한 파이프라인·빠른 실행 이력을 비교합니다. 실행별 통과율과 자동 복구 집계를 볼 수 있습니다.

기록 비교

유형·플랫폼·그룹 필터로 범위를 좁힌 뒤 실행 시각, 통과율, 통과 / 전체, 소요, 유형, 플랫폼, 그룹과 결과를 비교합니다. 재시도별 차이는 해당 실행의 증거 화면에서 확인하세요.

이 화면의 기록은 브라우저 localStorage에 저장됩니다. 다른 브라우저나 프로필에서는 같은 목록이 보이지 않을 수 있습니다. 기록 초기화는 이 목록을 초기화하며, 서버의 HTML 리포트 삭제는 리포트 화면에서 별도로 수행합니다.

환경 설정

Appium과 Android 에뮬레이터·iOS 시뮬레이터·실기기를 준비하는 화면입니다. 실행·작성 화면의 기기 선택과 연결 상태를 함께 확인합니다.

Appium 상태 읽기

상태설명과 다음 작업
stopped서버가 중지되어 있습니다. 환경 설정의 시작 버튼으로 준비합니다.
starting시작 중입니다. 상태가 갱신될 때까지 기다리고 로그를 확인합니다.

external별도로 실행된 서버입니다. 중지 동작은 현재 실행 중인 서버를 종료하므로 확인 창을 읽습니다.
error기동에 실패했습니다. 로그에서 원인을 확인한 뒤 다시 시작합니다.

터미널에서 직접 시작한다면 설치된 Android SDK 경로에 맞춰 ANDROID_HOME을 설정합니다. Android 미러링은 서버의 --allow-insecure=uiautomator2:adb_screen_streaming 설정도 확인합니다.

기기 준비와 연결 정책

  • Android 에뮬레이터: 등록된 AVD를 시작하고 실행 중 상태를 확인합니다. Appium과 기기는 각각 준비해야 합니다.
  • Android 실기기: USB 디버깅을 허용하고 연결을 확인합니다. 필요한 경우 추가 또는 WiFi 페어링을 사용합니다.
  • iOS 시뮬레이터: 등록된 시뮬레이터를 시작한 뒤 앱 Bundle ID와 실행 대상을 확인합니다.
  • iOS 실기기: 기기 신뢰·연결과 개발 환경을 준비합니다. 필요한 경우 WDA 빌드에서 WebDriverAgent 준비 상태를 확인합니다.

등록 정보는 config/devices.json에서 관리합니다. 기본 기기 표시와 현재 선택된 기기는 구분해서 확인하세요. 실행 화면은 연결된 기기만 선택할 수 있고, 새로고침 후 연결이 끊긴 대상은 선택에서 제외됩니다.

WiFi 페어링·WDA 빌드 대화창은 입력·상태를 확인한 뒤 닫습니다. Escape로도 닫을 수 있습니다. 같은 기기에서 Capture와 테스트를 동시에 실행하지 마세요.

자주 묻는 질문

빠른 실행에 폴더가 없거나 구버전 코드 안내가 나옵니다.

TC 스튜디오에서 Markdown을 내보냈는지 확인하고 파이프라인의 코드 생성·린트 검사를 진행하세요. Capture에서 작성했다면 저장 및 생성 결과를 확인합니다. 빠른 실행에서 해당 플랫폼을 선택하고 목록을 다시 읽어 확인합니다.

기기를 선택할 수 없습니다.

환경 설정에서 실제 연결 상태를 확인한 뒤 실행 화면의 기기 새로고침을 누릅니다. 미연결 항목은 비활성화됩니다. Android와 iOS에서 각각 대상 기기가 선택되어 있는지 확인하세요.

Capture 미러링이 멈추거나 세션 충돌이 발생합니다.

같은 플랫폼의 테스트 실행과 충돌한다면 Capture 세션을 종료한 뒤 테스트를 실행합니다. 연결만 끊겼다면 Appium·기기·앱 정보를 확인한 뒤 현재 작업 화면의 세션 재연결을 사용합니다. Android 미러링은 스트리밍 허용 설정과 MJPEG 포트도 확인합니다.

영상이나 스크린샷이 없습니다.

실패 시만 보존 정책에서는 정상 통과 증거가 남지 않을 수 있습니다. 시도별 수집 오류·지원 대상과 보존 여부를 확인합니다. 파일이 없다는 표시를 테스트가 통과했다는 의미로 해석하지 마세요.

최종 통과인데 처음 시도는 실패했습니다.

설정된 재시도 후 통과한 경우입니다. 최종 통과 합계와 함께 시도별 오류·증거를 확인합니다. 실행 증거 화면의 FLAKY 표시는 불안정한 결과를 찾는 데 사용합니다.

다른 브라우저에서 실행 기록이 보이지 않습니다.

실행 기록은 브라우저별 저장소에 있습니다. 서버의 저장된 결과는 리포트 목록과 실행 증거에서 별도로 확인하세요.

엑셀을 잘못 가져오거나 파일을 덮어쓸까 걱정됩니다.

엑셀 가져오기 이력에서 해당 작업의 되돌리기를 먼저 확인합니다. 내보내기는 경로·충돌·덮어쓰기 선택을 미리보기에서 확인한 뒤 반영합니다. TC 전체 삭제와 개별 가져오기 되돌리기는 서로 다른 작업입니다.
