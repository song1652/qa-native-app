QA Dashboard 페이지별 사용법

Appium 기반 Android·iOS 자동화 테스트를 대시보드에서 관리하는 방법을 페이지 순서대로 설명합니다. 각 섹션은 화면에서 무엇을 하는지, 어떤 순서로 사용하는지에 집중합니다.

📊
개요

Dashboard

프로젝트 전체 현황을 한눈에 볼 수 있는 홈 화면입니다. 최근 실행 결과와 Appium 연결 상태를 확인하고, 다른 탭으로 이동하는 출발점으로 사용합니다.

타일은 자동으로 갱신됩니다. Appium 상태 타일을 클릭하면 환경 설정 탭으로 이동합니다.

🔄 파이프라인 상태

가장 최근에 실행된 파이프라인의 단계별 진행 상황 (분석 → 생성 → 린트 → 실행 → 힐링)이 색상 뱃지로 표시됩니다. 실행 중이면 실시간으로 업데이트됩니다.

📋 최근 실행 히스토리

최근 5건의 실행 기록이 목록으로 표시됩니다. 날짜·플랫폼·결과를 확인하고, 상세 리포트로 이동할 수 있습니다.

💡
빠른 실행 완료 후 KPI 갱신
빠른 실행이 완료되면 Dashboard의 KPI와 히스토리가 자동으로 갱신됩니다. 탭을 전환하지 않아도 됩니다.
⚙️
환경

환경 설정

Appium 서버와 테스트 디바이스(에뮬레이터·시뮬레이터·실기기)를 관리합니다. 파이프라인 실행과 Capture Studio를 사용하기 전에 여기서 환경을 먼저 준비해야 합니다.

🔌 Appium 서버

대시보드에서 Appium을 시작·중지하거나, 터미널에서 별도로 실행 중인 Appium 상태를 확인합니다.

상태의미가능한 액션
stopped Appium이 실행되지 않음 ▶ 시작
starting 기동 중 (잠시 대기) 대기
managed 대시보드가 직접 관리 중 ■ 중지, 🔄 재시작
external 터미널에서 별도 실행 중 ■ 중지 (lsof로 PID 탐색 후 종료)
error 시작 실패 또는 예기치 않은 종료 "다시 시도" 클릭
⚠️
Appium 필수 환경변수
터미널에서 Appium을 직접 실행할 때는 반드시 ANDROID_HOME을 먼저 설정하세요.
export ANDROID_HOME=/Users/junghoyoung/Library/Android/sdk
🤖 Android 에뮬레이터
1
에뮬레이터 목록 확인
config/devices.json에 등록된 AVD 목록이 표시됩니다. 각 항목의 기본(default) 뱃지를 확인합니다.
2
▶ 시작 클릭
기본 에뮬레이터가 비동기로 기동됩니다. 상태가 부팅 중... → 실행 중으로 전환됩니다.
3
Appium 연결 확인
에뮬레이터가 실행 중이고 Appium이 managed 또는 external이면 파이프라인 실행 또는 Capture Studio 진입이 가능합니다.
💡
에뮬레이터는 Appium 상태와 무관하게 시작할 수 있습니다. Appium이 stopped 상태여도 에뮬레이터를 먼저 켜두고 이후 Appium을 시작해도 됩니다.
🍎 iOS 시뮬레이터
1
시뮬레이터 목록 확인
config/devices.json의 ios.simulator[] 목록이 표시됩니다. default: true인 항목이 자동으로 선택됩니다.
2
▶ 시작 클릭
API가 즉시 202를 반환하고 시뮬레이터가 백그라운드에서 기동됩니다. 부팅 중... 상태가 30–60초 표시된 뒤 실행 중으로 자동 전환됩니다.
3
bundle_id 설정 확인
Capture Studio에서 iOS 세션을 열려면 config/test_data.json에 bundle_id가 정확히 등록되어 있어야 합니다.
⚠️
iOS 세션 충돌 주의
시뮬레이터당 Appium 세션은 1개만 허용됩니다. Capture Studio iOS 세션이 열려 있으면 iOS 파이프라인을 동시에 실행할 수 없습니다 (반대도 동일). 충돌 시 "🔄 세션 재연결" 버튼으로 복구합니다.
📥
TC 작성

Import Studio

Excel로 작성된 테스트케이스를 대시보드에서 바로 임포트합니다. 열 매핑부터 미리보기·충돌 확인·반영까지 5단계로 안전하게 TC를 등록합니다.

📂 사전 준비

임포트할 .xlsx 파일을 프로젝트 루트의 import/ 폴더에 미리 넣어 두세요. 원본 파일은 수정되지 않습니다.

🗂️ 5단계 임포트 흐름
1
파일 선택
import/ 폴더의 파일 목록에서 원하는 .xlsx를 클릭합니다.
2
시트 선택
파일 내 시트 목록이 표시됩니다. 하나 이상의 시트를 체크하고, 플랫폼(Android·iOS·양쪽)을 선택합니다.
3
열 매핑
Excel의 어느 열이 tc_id·title·precondition·steps·expected에 해당하는지 드롭다운으로 지정합니다. 매핑이 바뀔 때마다 미리보기가 자동 갱신됩니다.
4
미리보기 확인
전체·추가·업데이트·충돌·오류·동일 필터로 TC 상태를 확인합니다. 충돌 TC는 기존 파일이 남아 있는 항목입니다.
5
반영 (안전한 적용)
기본 정책은 skip-conflict — 충돌 TC는 기존 Markdown을 유지합니다. 덮어쓰려면 "overwrite" 모드를 선택한 뒤 반영합니다.
📁 생성 경로 규칙

시트명이 폴더가 됩니다. 시트명 자체가 android나 ios이면 플랫폼 루트 바로 아래에 생성됩니다 (중첩 폴더 없음).

시트: login / 플랫폼: Android+iOS
→ testcases/android/login/TC-001.md
→ testcases/ios/login/TC-001.md
✅
임포트 완료 후 파이프라인 실행 탭에서 바로 분석·생성을 진행할 수 있습니다.
🎬
TC 작성

Capture Studio

실제 앱 화면을 보면서 탭·스크롤 등 동작을 기록하고, Locator를 승인한 뒤 자동으로 pytest TC 파일을 생성합니다. Excel 없이 TC를 직접 만드는 방법입니다.

🔌 사전 준비
①
Appium 실행 확인
환경 설정 탭에서 Appium이 managed 또는 external 상태인지 확인합니다.
②
디바이스 준비
Android: 에뮬레이터가 실행 중이어야 합니다. iOS: 시뮬레이터가 실행 중이어야 합니다.
🎯 TC 생성 흐름
1
세션 설정 — TC 정보 입력
플랫폼, tc_group(폴더명), tc_id(파일명)를 입력합니다. 예: group=login, id=tc_login_v1 → tests/generated/android/login/tc_login_v1.py
2
세션 시작 — 앱 화면 미러링
Android는 MJPEG 스트리밍(포트 8093), iOS는 XCUITest polling(1.2초 간격)으로 화면이 표시됩니다. 연결에 실패하면 "🔄 세션 재연결" 버튼을 클릭합니다.
3
요소 선택 — Hierarchy 트리
우측 패널에 앱 UI hierarchy가 트리 형태로 표시됩니다. 클릭하면 해당 요소가 선택되고, Locator 후보가 자동 생성됩니다. 화면이 바뀌면 4초 이내에 hierarchy가 자동 새로고침됩니다.
4
동작 기록 — 액션 추가
Tap · Scroll · Back · Wait 액션을 순서대로 추가합니다. 목록에서 드래그로 순서를 바꾸거나 삭제할 수 있습니다. Back 액션 실행 후 1.2초 뒤에 hierarchy가 자동 새로고침됩니다.
5
Locator 승인
각 Tap 동작에 대한 Locator 후보(resource-id / content-desc / text 등)가 표시됩니다. 가장 안정적인 후보를 선택해 승인합니다.
6
저장 및 생성
"저장 및 생성" 버튼을 클릭하면 tests/generated/{platform}/{tc_group}/{tc_id}.py에 자체 완결형 pytest 파일이 생성됩니다. 드라이버 초기화·헬퍼 함수·테스트 클래스가 한 파일에 포함됩니다.

② 동작을 하나씩 알려주기
1
검색창을 선택하고 탭 기록
Hierarchy에서 search_action_bar를 클릭합니다. Locator 후보의 검증을 눌러 유일 (1개 매칭)인지 확인하고 👆 탭을 누릅니다. 그다음 에뮬레이터의 검색창을 직접 눌러 실제 검색 화면으로 이동합니다.
2
화면이 열릴 시간을 주기
오른쪽의 요소 없이 추가에서 ⏱ 대기를 누르고 2를 입력합니다. 검색 화면이 완전히 열린 뒤 다음 동작을 하도록 만드는 안전장치입니다.
3
입력 필드 선택
화면이 바뀌었으므로 Hierarchy 새로고침을 누릅니다. Hierarchy에서 open_search_view_edit_text를 선택하고 Locator가 유일 (1개 매칭)인지 검증합니다.
4
Bluetooth 입력 기록
에뮬레이터 검색창에 실제로 Bluetooth를 입력합니다. Capture Studio에서 ⌨ 입력을 누르고 똑같이 Bluetooth를 적은 뒤 기록을 누릅니다.
5
입력 결과를 기다리기
다시 ⏱ 대기를 누르고 2를 입력합니다. 입력 직후 결과가 바뀌는 동안 테스트가 너무 빨리 넘어가지 않게 합니다.
6
Bluetooth 글자 검증
입력 필드가 선택된 상태에서 ✓ 검증 → 📝 텍스트 확인을 누릅니다. 확인할 텍스트에 Bluetooth를 입력하고 확인을 누릅니다.
👆 검색창 탭→ ⏱ 2초→ ⌨ Bluetooth 입력→ ⏱ 2초→ ✓ Bluetooth 확인
③ 저장하고 실행하기
7
TC 이름 입력 후 저장·생성
TC ID에 tc_capture_settings_search_input, 제목에 설정 검색창 텍스트 입력과 검증을 입력합니다. 미리보기에서 다섯 단계가 맞는지 확인한 뒤 저장 및 생성을 누릅니다. 테스트 코드 생성 완료가 표시되면 성공입니다.
8
Capture 세션 종료
세션 종료를 누릅니다. Capture 세션이 열린 상태에서는 빠른 실행과 같은 플랫폼의 Appium 세션이 충돌할 수 있습니다.
9
빠른 실행에서 확인
빠른 실행으로 이동해 Android를 선택합니다. 다른 항목의 체크를 풀고 capture_studio_e2e만 선택한 뒤 테스트 실행을 누릅니다. 실행 중 에뮬레이터에서 검색창이 열리고 Bluetooth가 자동 입력됩니다.
완료 기준: Chrome에 ALL PASS, 1 PASSED / 0 FAILED, 실행 완료 (1/1)이 표시됩니다.
생성 파일: tests/generated/android/capture_studio_e2e/tc_capture_settings_search_input.py
🔁
같은 테스트를 다시 실행해도 자동으로 시작 화면을 맞춥니다
에뮬레이터·시뮬레이터 전체를 초기화할 필요는 없습니다. 빠른 실행은 테스트를 시작할 때마다 이전 앱 화면을 닫고 대상 앱을 다시 열어 정해진 시작 화면으로 돌려놓습니다. 자동 복구 자체가 실패했다는 안내가 나타날 때만 기기가 켜져 있는지 확인하고 앱을 직접 한 번 연 뒤 다시 실행하세요.
⚠️
미러 화면은 눌러도 단계가 두 번 생기지 않습니다
Hierarchy에서 👆 탭을 추가한 뒤 미러 화면을 눌러 실제 기기를 움직여도, 수동 STEP 모드에서는 같은 탭이 Action Timeline에 자동 추가되지 않습니다. 저장 전에는 위에 표시된 다섯 단계가 맞는지만 확인하세요.
🩹 Healing 연계

파이프라인 실행에서 TC가 실패한 경우, 실패 TC를 클릭하면 Capture Studio로 재진입해 Locator를 4단계부터 재검토할 수 있습니다. hierarchy는 실패 직전 스냅샷이 자동으로 로드됩니다.

🤖 Nova MCP — Claude Code로 디바이스 직접 제어

Capture Studio 세션이 열린 상태에서 Claude Code가 MCP 툴을 호출하면, 대시보드 상단 칩이 MCP ON으로 전환됩니다. Claude에게 말하는 것만으로 스크린샷 촬영·탭·스크롤·TC 생성이 가능합니다.

⚙️ 1회 설정 — Claude Code에 MCP 서버 등록

.claude/settings.json (또는 전역 ~/.claude/settings.json)에 아래 블록을 추가합니다.

{
  "mcpServers": {
    "qa-capture-studio": {
      "url": "http://localhost:8767/mcp"
    }
  }
}

설정 후 Claude Code를 재시작하면 MCP 서버가 인식됩니다.

💬 사용 방법
1
Capture Studio 세션 먼저 시작
세션이 없으면 MCP 툴 호출 시 session_not_active 에러가 반환됩니다.
2
Claude Code에 자연어로 요청
예시 발화: "현재 화면 스크린샷 찍어줘" / "지금 화면 hierarchy 가져와줘"
Claude가 MCP 툴을 호출하는 순간 대시보드 칩이 MCP ON으로 전환됩니다.
3
수동 OFF
상단 MCP 칩을 클릭하면 확인 후 세션이 해제됩니다. 다시 ON은 Claude에게 말하면 자동 재연결됩니다.

파이프라인 실행

분석 → 생성 → 린트 → 실행 → 힐링 5단계를 순서대로 실행하는 전체 파이프라인입니다. TC Markdown을 입력으로 받아 실행 리포트까지 자동으로 생성합니다.

단계하는 일
01 분석Appium으로 앱에 연결해 native UI hierarchy와 WebView DOM을 수집합니다. 결과는 state/pipeline.json에 저장됩니다.
02 생성TC Markdown과 Locator registry를 기반으로 pytest 파일을 생성합니다. --strict-locators 모드에서 locator 누락 시 실패합니다.
03 린트생성된 코드를 flake8로 검사합니다. 오류가 있으면 이 단계에서 멈춥니다.
05 실행pytest로 생성된 TC를 실행합니다. pytest-rerunfailures가 설치된 경우 실패 TC를 2회 자동 재시도합니다.
06 힐링실패 TC에 대해 hierarchy를 재수집하고 유일한 후보 locator만 자동으로 갱신합니다. 3회 재시도 후에도 실패하면 Jira 버그가 생성됩니다.
▶️ 실행 방법
1
플랫폼 선택
Android 또는 iOS를 선택합니다. 각각 독립적으로 실행됩니다.
2
실행 시작
"전체 파이프라인 실행" 버튼을 클릭합니다. 단계별 진행 상황이 실시간으로 업데이트됩니다.
3
결과 확인
완료 후 리포트 링크가 제공됩니다. 실패 TC가 있으면 힐링 결과와 함께 표시됩니다.
⚠️
세션 충돌 방지
파이프라인 실행 중에는 같은 플랫폼의 Capture Studio 세션을 열 수 없습니다. 대시보드 상단에 충돌 상태가 표시됩니다.

빠른 실행

전체 파이프라인 없이 이미 생성된 TC 파일을 바로 pytest로 실행합니다. 특정 그룹이나 개별 파일만 선택해서 빠르게 검증할 때 사용합니다.

☑️ 사용 방법
1
플랫폼 탭 선택
Android 또는 iOS 탭을 클릭합니다. 각 탭에는 해당 플랫폼의 생성된 TC 그룹과 파일이 표시됩니다.
2
TC 선택
그룹 단위로 전체 선택하거나 개별 파일을 체크합니다. 선택한 탭 내 체크박스만 실행에 포함됩니다.
3
실행
"선택 항목 실행" 버튼을 클릭합니다. pytest 출력이 실시간으로 표시되고, 완료 후 Dashboard KPI와 히스토리가 자동 갱신됩니다.
💡
빠른 실행은 분석·생성·린트 단계를 건너뛰고 pytest 실행만 합니다. TC 파일이 최신 상태인지 먼저 확인하세요. 파일이 없으면 파이프라인 실행에서 02 생성까지 먼저 진행합니다.
